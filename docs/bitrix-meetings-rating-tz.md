# ТЗ: рейтинг операторов по назначенным встречам (Bitrix24)

## 1) Цель
Сделать простой веб-интерфейс на **чистом HTML/CSS/JS** + **простой сервер** (Node.js + Express), который показывает:
- рейтинг сотрудников, назначивших встречи **сегодня**;
- общее количество назначенных встреч за день;
- лидера дня;
- всплывающее уведомление при появлении нового назначения встречи.

## 2) Границы MVP
В MVP входим:
1. Получение данных из Bitrix24 через входящий webhook.
2. Фильтрация сделок по этапу "Назначена встреча" и дате "сегодня".
3. Агрегация количества встреч по ответственному сотруднику.
4. Отображение рейтинга на одной HTML-странице.
5. Автообновление данных каждые 15–30 секунд.
6. Toast-уведомление при росте счётчика у сотрудника.

В MVP **не входим**:
- авторизация пользователей в интерфейсе;
- хранение истории за прошлые дни в БД;
- сложные роли/доступы;
- интеграция в существующий интерфейс МГБ.

## 3) Архитектура (простая)
- **Backend**: Node.js + Express.
- **Frontend**: `public/index.html`, `public/styles.css`, `public/app.js`.
- **Интеграция Bitrix**: REST webhook (`crm.deal.list`, `user.get`).
- **Хостинг**: любой VPS/локальный сервер.

Поток данных:
1. Frontend запрашивает `GET /api/meetings/today`.
2. Backend обращается в Bitrix REST.
3. Backend агрегирует данные и возвращает JSON.
4. Frontend рендерит рейтинг и сравнивает с прошлым состоянием.
5. Если есть рост — показывает toast.

## 4) Переменные окружения
Обязательные:
- `BITRIX_WEBHOOK_URL` — базовый URL входящего webhook.
- `BITRIX_MEETING_STAGE_ID` — ID этапа "Назначена встреча".

Опциональные:
- `PORT` — порт сервера (по умолчанию `3000`).
- `POLL_INTERVAL_MS` — период автообновления (по умолчанию `30000`).
- `TZ` — таймзона, например `Asia/Almaty`.

## 5) API сервера
### `GET /api/meetings/today`
Возвращает текущий рейтинг за сегодняшний день.

Пример ответа 200:
```json
{
  "generatedAt": "2026-03-13T08:20:00.000Z",
  "summary": {
    "totalMeetings": 17,
    "activeEmployees": 5
  },
  "stats": [
    {
      "employeeId": "23",
      "employeeName": "Иванов Иван",
      "position": "Оператор",
      "meetingsCount": 6
    }
  ]
}
```

Пример ответа 500:
```json
{
  "error": "Bitrix API error message"
}
```

## 6) Логика подсчёта
1. Берём текущую дату в согласованной таймзоне.
2. Формируем границы дня: `00:00:00`–`23:59:59`.
3. Запрашиваем сделки:
   - `STAGE_ID == BITRIX_MEETING_STAGE_ID`
   - дата изменения/входа в этап в пределах текущего дня (уточняется при интеграции по доступным полям).
4. Группируем по `ASSIGNED_BY_ID`.
5. Подтягиваем ФИО/должность через `user.get`.
6. Сортируем по убыванию `meetingsCount`.

> Важно: на этапе интеграции проверить, какое поле в вашей воронке корректно отражает момент "назначена встреча" (часто это `DATE_MODIFY`, но может потребоваться поле истории стадий/кастомное поле).

## 7) UI требования (HTML)
На странице должны быть:
1. Заголовок: "Рейтинг встреч за сегодня".
2. KPI-блоки:
   - всего назначено;
   - активных сотрудников;
   - лидер дня.
3. Список/таблица рейтинга:
   - место;
   - ФИО;
   - должность;
   - количество встреч.
4. Кнопка "Обновить".
5. Метка "Обновлено в HH:MM:SS".
6. Toast-уведомление (правый верхний угол), текст вида:
   - "Вау, красавчик! [Имя] назначил(а) новую встречу 👏"

## 8) Нефункциональные требования
- Время ответа API (без деградации Bitrix): до 2–3 сек.
- Обработка ошибок Bitrix без падения сервера.
- Логи ошибок в stdout.
- Код без фреймворков на фронте (vanilla JS).

## 9) Обработка ошибок
Backend:
- если `BITRIX_WEBHOOK_URL` не задан — `500` + понятный текст;
- если Bitrix вернул ошибку/не 200 — `500` + сообщение;
- если данных нет — `200` и пустой `stats`.

Frontend:
- если API недоступен — показывать блок ошибки;
- при восстановлении API — автоматически убирать ошибку после успешного запроса.

## 10) Безопасность
- webhook хранить только в `.env`, не публиковать в клиенте;
- CORS ограничить своим доменом (если нужен внешний доступ);
- rate limit на endpoint (минимальный).

## 11) План реализации (следующий этап)
1. Создать скелет Express-сервера.
2. Реализовать модуль Bitrix API-клиента.
3. Реализовать endpoint `/api/meetings/today`.
4. Сделать HTML-страницу и рендер рейтинга.
5. Добавить polling и toast-уведомления.
6. Протестировать на реальных данных Bitrix.
7. Упаковать в `README` с запуском.

## 12) Критерии приёмки
- При открытии страницы показывается рейтинг за текущий день.
- Если сегодня встреч нет — корректное пустое состояние.
- При увеличении количества у любого сотрудника появляется toast.
- Обновление происходит автоматически и вручную кнопкой.
- Настройка через `.env` работает без правки кода.
